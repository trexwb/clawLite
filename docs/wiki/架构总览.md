# 架构总览

## 一、进程模型

```
主进程 electron/main.ts（ESM 产物 dist-electron/main.js）
  ├─ 单实例锁、窗口、菜单、生命周期、自动更新
  ├─ registerIpc()：全部 ipcMain.handle 通道
  └─ HarnessManager（electron/harness.ts）──spawn──> dsh web 子进程（监听 127.0.0.1）
        │
        │  contextBridge（sandbox: true / contextIsolation: true / nodeIntegration: false）
        ▼
桥 electron/preload.ts（CJS 产物 dist-electron/preload.js，暴露 window.clawLite）
        │
        ▼
渲染层 src/（Vite 构建到 dist/，深色控制台 UI，纯原生 JS 无框架）
```

- **DSH 子进程由主进程 spawn**，不进渲染层。
- **渲染层**经 `BrowserWindow.loadFile` 加载 `dist/index.html`（`base: './'`，保证 `file://` 下资源路径正确）。
- **源码与产物后缀**：`electron/`、`scripts/`、`src/` 源码一律 `.ts`；产物一律 `.js`（`dist/`、`dist-electron/`），仓库不出现 `.cjs` / `.mjs`。

## 二、分层职责

| 层 | 文件 | 职责 |
|---|---|---|
| 主进程 | `electron/main.ts` | 单实例锁、窗口、IPC 路由、菜单、生命周期、更新检查 |
| 桥 | `electron/preload.ts` | `contextBridge` 暴露 `window.clawLite`（方法 + `onState` / `onLog` / `onVersionProgress` 事件订阅） |
| 运行时托管 | `electron/harness.ts` | `HarnessManager`：dsh 子进程 spawn / 探活 / 日志 / 状态机 / 优雅停止 / 版本解析 |
| 版本获取与下载 | `electron/version-fetch.ts`、`electron/version-download.ts` | 版本列表拉取、异步下载与进度上报 |
| 设置 | `electron/settings.ts` | 配置持久化（`userData/settings.json`） |
| 渲染层 | `src/` + `index.html` | Vite 构建到 `dist/`，深色控制台 UI |
| 共享常量 | `src/shared/constants.ts` | 端口范围、日志上限等跨进程单一来源（纯常量，无 Node API） |
| 内置运行时 | `resources/dsh/` | `app/node_modules/@deepseek-ai/dsh` + `runtime.json` 清单 |

## 三、IPC 契约三层对齐

新增或修改主进程能力时，三处必须同步改，否则 `npm run check` 会红灯：

1. `electron/main.ts` 的 `ipcMain.handle('channel', …)`
2. `electron/preload.ts` 暴露的方法 / 事件订阅
3. `src/main.ts` 的 `api.*` 调用

**主进程通道（节选）**：`harness:snapshot` / `harness:start` / `harness:stop` / `harness:restart` / `harness:verify` / `harness:clearLogs` / `harness:listVersions` / `harness:prepareVersion` / `harness:applyVersion` / `harness:cancelVersion` / `harness:pruneVersions` / `harness:saveSettings` / `harness:open` / `dialog:pickDirectory` / `updater:check` / `app:relaunch` / `app:info`

**广播事件**：`harness:state`（推送整体快照）/ `harness:log`（推送单行字符串，空串表示清屏）/ `harness:versionProgress`（推送版本下载任务状态）

> 通道名、方法名与渲染层调用名的完整清单以 `electron/preload.ts` 与 `scripts/check.ts` 的校验项为单一来源。

## 四、状态机

`HarnessManager.state` 共 6 态：`notInstalled` / `stopped` / `starting` / `stopping` / `running` / `error`，由 `setState()` 统一驱动并经 `harness:state` 广播。

渲染层 `STATE_LABEL` 必须**双向对应**：既覆盖全部取值（无状态无文案），也全部可达（无死枚举）。`scripts/check.ts` 对两个方向各有硬断言。

- `stopping` 由 `stop()` 置入，收尾解除；
- `starting` 与 `stopping` 期间渲染层均视为忙碌；
- 启动探活阶段（子进程已起、快照 `canStop` 为真）**允许**点「停止」中止本次启动，其余操作禁用。

## 五、数据流

```
用户操作 → 渲染层 call('harness_*') → preload api.* → ipcMain.handle('harness:*')
                                                                ↓
                                             HarnessManager 状态 / 子进程变更
                                                                ↓
                                             setState() / log() → emit('state' / 'log')
                                                                ↓
                                    main.ts broadcast('harness:state' / 'harness:log')
                                                                ↓
                                            渲染层 onState(snap) → render(snap)
                                            渲染层 onLog(line)  → 着色后追加日志
```

访问地址捕获（带 token 的信任凭据）：

```
dsh 子进程 stdout → attachPipes → log(line) → _captureUrl(line) 匹配
  `dsh web: http://127.0.0.1:<port>/?token=xxx` → this.url → emit('state')
```

## 六、安全基线（不得放宽）

- `contextIsolation: true` / `nodeIntegration: false` / `sandbox: true`
- 严格 CSP：`default-src 'self'`、`script-src 'self'`、`connect-src 'self'`（`style-src` 的 `'unsafe-inline'` 仅为 Vite 开发模式 HMR 保留，脚本侧不放宽）
- 主窗口与被托管的 dsh web 窗口均挂 `will-navigate` 守卫，只放行自身入口 / 同源站内导航，其余交系统浏览器
- 渲染层禁用 `innerHTML` 注入未转义内容
- DSH 访问 token 仅存于内存，不落盘
