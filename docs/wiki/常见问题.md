# 常见问题

## 安装与打开

**Q：macOS 提示「应用已损坏，无法打开」或「无法验证开发者」？**

先确认**已把 Claw Lite 拖入「应用程序」文件夹**再打开（直接从 DMG 只读卷运行会被系统拦住拉起内置运行时，应用会主动提示）。

若仍被 Gatekeeper 拦截，在「终端」执行：

```bash
xattr -dr com.apple.quarantine "/Applications/Claw Lite.app"
```

然后从「应用程序」重新打开。该命令只清除系统给应用打的隔离属性，不修改应用内容；正式分发的签名 / 公证版无需此步。

**Q：为什么双击 DMG 里的应用会提示「请先把应用拖入应用程序文件夹」？**

macOS 不允许从只读磁盘映像内运行的应用拉起内置运行时。拖入「应用程序」后即可正常工作。

**Q：Windows 上首次启动弹出防火墙提示？**

dsh web 监听 `127.0.0.1` 本地回环，仅在需要访问局域网 / 被外部访问时才需要放行；日常使用可点「取消」。若已勾选允许，可稍后在 Windows 防火墙设置中调整。

## 启动与运行

**Q：点「启动」后一直起不来？**

先看界面上的运行日志区（错误行会高亮）：

- 日志提示运行时缺失 → 开发环境请先执行 `npm run runtime`；安装包用户请确认应用是从「应用程序」目录运行；
- 端口相关报错 → 见下一条；
- 若状态停在 `starting` 很久 → dsh 首次启动需探活，最长 60 秒；探活期间可点「停止」中止本次启动。

**Q：提示端口被占用？**

默认端口 8799，可用范围 1024–65535。配置的端口被占用时应用会自动挑选空闲端口。若自定义端口总被占用，可改回默认或换一个高位端口。

**Q：dsh web 界面白屏 / 打开被拒？**

访问地址必须是**带 token 的完整 URL**（形如 `http://127.0.0.1:8799/?token=...`）——token 是 dsh Web UI 的信任凭据，缺了会被拒。请用「复制」按钮取完整地址，不要手工拼 `http://127.0.0.1:端口`。

**Q：开发模式下白屏？**

开发模式渲染层由 Vite 提供，端口固定为 **5173**（`strictPort`），不是 1420。请用 `npm run dev` 启动后再以 `CLAWLITE_DEV_SERVER=http://localhost:5173 npm run electron` 打开。

## 版本与更新

**Q：为什么安装包这么大（约 300MB / dmg 约 150MB）？**

安装包内置了完整的 dsh 依赖树，其中 `node-pty`、`sharp` 等平台相关原生模块必须解包为真实文件（不能放进 asar），体积换来的正是「用户免装 Node、开箱即用」。

**Q：能直接用最新的 dsh 版本吗？**

dsh v0.1.7 系列依赖更新版本的 Node / Electron，与项目当前锁定的 Electron 版本存在兼容冲突，因此内置运行时维持 `0.1.5-rc.3`。可在设置页手动选择其他版本试用（选定即下载，见 [[DSH-版本管理与热切换]]）。

**Q：切换 dsh 版本需要重启应用吗？**

不需要。下载完成后直接点「切换并启动」即可。

**Q：应用更新后我的配置还在吗？**

在。配置与 DSH 数据都存放在用户数据目录（macOS：`~/Library/Application Support/Claw Lite/`），升级安装不会清除。

## 开发与自检

**Q：`npm run check` 报错怎么处理？**

按报错项逐条修：IPC 三层对齐、状态枚举双向可达、日志着色类名与 CSS 交叉、端口范围三方一致、安全基线断言、源码后缀与类型检查、产物模块形态。这些断言存在的意义就是拦住「改动只落一处」的缺陷，不建议绕过。

**Q：`npm run check` 出现 1 项 WARN？**

多为本地未拉取内置 DSH 运行时（`resources/dsh/app` 不存在），与代码改动无关，执行 `npm run runtime` 即可消除。

**Q：`npm run build:web` 报找不到 Vite？**

仓库不含 `node_modules`，需先 `npm install`（Node ≥ 24）。

**Q：改了代码要写发布日志吗？**

要。每次迭代都要往 `docs/version/RELEASE-v{主版本}.md` 顶部追加分节，标注日期与版本号（正式发布后按语义化版本正常推进版本号，修复与文档 / 样式类改动推修订号；仅当用户明确要求不改版本号时才注明「不推进版本号」），历史日志只增不改。详见 [[自检与发布流程]]。
